# Architecture

## Design decisions

**GUI:** Python 3.10+ and PySide6 / Qt 6 widgets. Native desktop process, no browser, Chromium or privileged GUI. Qt I/O is scheduled through a single worker pool; the UI thread remains responsive while the controller waits for startup or the hosts helper waits for authorization.

**Runtime:** standard-library Python supervisor, with real native service executables. Default executables come from distro packages. Binary lookup preserves the caller PATH and additionally searches `/usr/sbin`, `/sbin`, `/usr/libexec` and `/usr/lib`, without globally changing the shell environment. Apache configuration has explicit `User #<effective-uid>` and `Group #<effective-gid>` directives at server scope, rather than relying on environment variables or assuming the primary group name matches the username. Their configuration and writable data are private. Users can point executable paths at their own compatible prefixes under `~/.local/share/localforge/runtimes/`. No AUR PHP packages, third-party RPM repositories or unverified binary downloads are added by the installer.

**Control:** newline-delimited JSON request/reply protocol over an AF_UNIX stream socket, mode 0600 in a mode-0700 runtime directory. Every peer must have the controller's UID according to `SO_PEERCRED`. The controller takes an exclusive `flock` to prevent concurrent ownership and serializes all engine mutations with an RLock. Requests are limited to 1 MiB and responses are bounded by the client. There is no remote TCP control API.

```text
Desktop session (ordinary user)
 ├─ PySide6 GUI ──── worker thread ──┐
 ├─ localforge CLI ─────────────────┤ same-UID Unix socket
 │                                 ▼
 │                       localforge.daemon
 │                       ├─ config + generation + project polling
 │                       ├─ syntax checks, bind probes, ss inventory
 │                       ├─ nginx OR httpd (foreground)
 │                       ├─ global php-fpm + project-version FPM masters (private sockets)
 │                       ├─ mariadbd OR mysqld (private datadir/socket)
 │                       ├─ redis-server OR valkey-server
 │                       └─ node /absolute/project/server.js
 │
 └─ GUI/CLI hosts action → pkexec → root-owned fixed-path helper
                                    └─ replaces ONLY invoking UID's hosts block
```

Without a nonempty `XDG_RUNTIME_DIR`, sockets live under the verified `/tmp/lf-<uid>/` fallback. Every managed Unix-socket pathname is validated by encoded byte length (a conservative 103-byte maximum). If the selected runtime directory is too long (including the longest allowed 40-character PHP label), all sockets and PID files move together to `/tmp/lf-<uid>/`. This directory is created with mode 0700 and opened with `O_NOFOLLOW`; an existing symlink, non-directory, foreign-owned directory or directory with permissions other than 0700 is rejected without attempting to repair it. The same validation runs in clients before connection. It is not automatically deleted because the controller lock and multiple same-user clients share it. Normal XDG base paths should not contain control characters; use conventional paths without whitespace for database option-file includes.

## Lifecycle and failure semantics

1. Validate service selection and configuration.
2. Test expected TCP port by binding to loopback; SO_REUSEADDR avoids treating TIME_WAIT as a listener conflict. This is a best-effort check: another process can take the port between check and launch.
3. For web servers, start the selected PHP-FPM pair first. A static-only web server still requires registered FPM in this release.
4. Perform offline syntax checks for Nginx, Apache and FPM. Vendor configuration is never included wholesale.
5. Spawn an argv list (`shell=False`) in a new process group, redirect logs, use private config paths and foreground flags.
6. Wait up to eight seconds for the expected listener, or twenty for the database; verify the launched master is still alive. This is a readiness heuristic, not HTTP/SQL application health validation.
7. Stop via the owned Popen process group with SIGTERM, then bounded SIGKILL escalation. PID files are never trusted for stopping/adopting arbitrary processes.

`Start all` is best effort per engine, not transactional. `Restart all` first stops all. Reload all reports unsupported services instead of inventing unsafe database or Redis signal behavior. Web reload signals are asynchronous: syntax validation cannot guarantee successful runtime reload, so inspect error logs.

**PHP switch:** verify registered executable availability, remember running PHP/web services, stop web then PHP, render configs, write selection and CLI shim, test FPM, restart prior services. On failure, restore the old selection/configs and attempt to restore prior services. Rollback errors are returned explicitly. Manual generated-file edits do not survive a switch; use persistent extras.

**Project discovery:** `.php-version` metadata is part of the fingerprint. Matching project selectors are resolved once per render for both web servers; required versioned FPM masters are syntax-checked and started before reload. Failure stops newly created masters and restores the prior includes. Existing unused override masters are retained until PHP stop/restart to avoid killing requests in older web workers. Explicit projects outside the scan root are also watched for selector changes.

**Project discovery:** the controller polls the project root every five seconds for additions, symlink target changes and appearance of `public/`. Valid lowercase directory names are registered automatically. Only vhost include files are changed during live discovery; custom top-level configs remain intact. A syntax-check failure restores the prior project list and include contents and is exposed as `discovery_error` in status. Deleted directories are not automatically unregistered: edit the project list deliberately. Host resolution is a separate authorized action.

**Full settings change:** all services must be stopped. Port changes and generated config writes occur together at the controller level, using atomic file replacements. This is not a crash-proof filesystem transaction across all files; interrupted operations can require reapplying settings. Full manual Scan also regenerates configs. These operations do not pre-validate every engine if its binary is missing; start/check does that.

## systemd and standalone mode

The installer generates a user-specific unit with an absolute virtualenv interpreter path, `UMask=0077`, `NoNewPrivileges=yes`, `KillMode=control-group`, restart-on-failure and a long enough stop timeout for all children. It enables the **controller**, not web/database engines; services do not auto-start after login until requested.

On normal shutdown the controller stops all owned services. Under systemd the cgroup also cleans up remaining descendants. Do not apply `PrivateTmp`/`ProtectHome` blindly to the unit: development code and project directories need user access.

GUI/CLI first connect, then try `systemctl --user start localforge.service`. If no user manager is available, they detach a standalone controller. Closing the GUI does not own the controller's lifetime. Use `localforge shutdown` to stop a standalone controller and all its services cleanly (or send SIGTERM after verifying the controller PID). An uncatchable standalone crash can leave children running: the next controller reports occupied ports rather than killing/adopting unverified PIDs. Prefer systemd for robust group cleanup.

The application intentionally does not enable user lingering. If you want controller lifetime beyond login, that is an explicit administrator policy decision (`loginctl enable-linger USER`).

## Source responsibility map

| File | Responsibility |
|---|---|
| `paths.py` | XDG paths, 0700 directories, atomic mode-0600 writes |
| `config.py` | Schema and input validation, binary discovery, runtime registry, project scan |
| `render.py` | Private configs and independently replaceable project vhosts |
| `php.py` | Bounded project selectors, versioned FPM lifecycle and pool status |
| `assets.py` | Hash-pinned offline Adminer deployment |
| `extensions.py` | One-time scoped system PHP database extension defaults |
| `engine.py` | Native process lifecycle, readiness, rollback, editor whitelist, status/logs |
| `daemon.py` | Unix RPC, peer credentials, lock, serialized engine operations, project poll |
| `client.py` | Bounded RPC and controller bootstrapping |
| `gui.py` | Native desktop interface, thread worker and tray |
| `cli.py` | Scriptable control surface |
| `hosts.py` | Unprivileged pkexec invocation with bounded input |
| `packaging/hosts-helper` | Narrow privileged hosts edit and metadata preservation |

## v0.1.2 socket and upgrade contract

Use `paths.mysql_socket`, `paths.php_socket`, and `paths.php_version_socket(label)` rather than reconstructing socket names at call sites. `paths.socket` remains the manager socket. Snapshot JSON exposes the global socket paths and a separate `php_pools` array of version, socket, PID, required flag and error state.

A changed renderer version or runtime base triggers regeneration on controller startup. Before doing so, existing generated configuration is copied to `~/.local/state/localforge/config-backups/<timestamp>/`. Versioned php.ini files and persistent extra includes are not replaced. Stop the **old installed controller** before upgrading; the installer checks both legacy and new standalone socket locations.
