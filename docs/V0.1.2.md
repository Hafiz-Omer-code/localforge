# v0.1.2: sockets, SELinux, Adminer and project PHP

## Upgrade from v0.1.1

1. Back up settings and database contents as usual.
2. With the **old installed** CLI, stop the controller (`localforge shutdown`), or stop the systemd user unit. Do not upgrade live Python code under a standalone controller.
3. Extract v0.1.2 and run the appropriate existing install script as your normal desktop user. The installer detects legacy and current standalone socket locations and refuses to upgrade while either is present.
4. Startup detects the changed renderer format. Existing generated configs are saved under `~/.local/state/localforge/config-backups/<timestamp>/`, then regenerated. Persistent `*-extra.conf`, `my-extra.cnf` and all versioned php.ini files are retained.
5. Start the stack, verify ports, open Adminer and test your applications. Reapply any deliberate top-level generated-file edits from the backup into persistent includes instead.

This remains a developer preview. Fedora enforcing-mode behavior and Arch package installation require actual desktop VM validation; passing tests in Debian do not certify either distribution.

## Unified paths

Backend code and integrations should consume:

```python
paths.socket                      # manager.sock
paths.mysql_socket                # mysql.sock
paths.php_socket                  # global php.sock
paths.php_version_socket("8.2")    # project master php-8.2.sock
```

`Paths` resolves the runtime directory exactly once. With normal XDG runtime paths it uses `$XDG_RUNTIME_DIR/localforge`. Missing/empty XDG_RUNTIME_DIR or any overlong managed pathname selects `/tmp/lf-<uid>`. The byte budget reserves space for the longest valid PHP label; one versioned socket cannot accidentally exceed the guard after startup. Existing mode-0700, same-UID, non-symlink fallback directories are reused; unsafe paths fail closed.

The daemon/client/renderer all consume this contract. Status JSON exposes `paths.mysql_socket` and `paths.php_socket`, and each `php_pools` entry contains its resolved versioned socket. The database integration test passes `--socket=<paths.mysql_socket>` and includes an actual SQL query through a shortened runtime path.

## SELinux context restoration

Immediately after the privileged helper/policy copies, the installer locates `restorecon` (including `/usr/sbin` and `/sbin`) and runs:

```bash
sudo restorecon -Rv /usr/lib/localforge /usr/share/polkit-1/actions
```

If the command is present but fails, installation stops rather than suppressing the error. No enforcement disablement or blanket allow policy is installed. Unit tests exercise command arguments and failure propagation using fake sudo/restorecon tools; they do not claim a real SELinux relabeling test.

## Offline Adminer bundle

- Upstream Adminer **6.1.2**, MySQL/MariaDB English build, is included in the wheel and source archive, with its SHA-256, provenance and Apache 2.0 license.
- It is copied into `~/.local/share/localforge/welcome/adminer.php` (respecting XDG_DATA_HOME) only after its bundled hash verifies. No mutable `latest.php` download occurs at install or runtime.
- **Open Adminer** launches `http://localhost:<http-port>/_adminer`.
- The global/default PHP runtime executes it, independent of project overrides.
- Nginx uses an exact location, absolute SCRIPT_FILENAME, resolved global FPM socket and a manager-generated FastCGI parameter include. It does not return a static PHP file or depend on distro-specific `fastcgi_params` paths.
- Apache supports the same route with an exact AliasMatch, local/Host access conditions and explicit proxy-FCGI handler. Its default DocumentRoot is `welcome/public`, outside the bundled PHP source file.
- The route is only on the default host and requires Host `localhost` or `127.0.0.1`. Normal project virtual hosts do not inherit it. Loopback exposure is not a multi-user security boundary; retain Adminer's database authentication.

Set the Adminer **Server** field to `127.0.0.1:<database-port>`. Create a password-protected development account using the OS-user MariaDB socket account as documented in RUNTIMES.md. Adminer does not log in using the OS-user passwordless socket account. No credentials are saved by LocalForge.

The distro `system` runtime receives one-time database extension defaults when compatible module files are installed. LocalForge introspects only the matching CLI under `-n`; it adds dependency-ordered module paths to a private conf.d file, never edits `/etc/php*`, never loads arbitrary system ini files and does not configure custom labels. Existing private defaults are preserved. If modules are absent, install/configure them for that runtime; Adminer cannot replace a missing PHP database driver.

## Project-root .php-version

```bash
# Register these runtime pairs first. Their actual compatible binaries must exist.
printf '%s\n' '8.2' > ~/www/legacy-app/.php-version
printf '%s\n' '8.3' > ~/www/modern-app/.php-version
```

A small, UTF-8 regular file at the **project root**, not its `public/` directory, may select an exact registered label. Absent, unreadable, symlink/FIFO, oversized, invalid-UTF-8 and unregistered values select the global default. Registered-but-broken FPM executables produce a failure rather than silently changing PHP ABI.

Both Nginx and Apache route matching projects to `php-<label>.sock`; unpinned projects use `php.sock`. A per-label FPM master has its own config, PID, socket, error/output logs and the selected label's ini/conf.d. Projects sharing a label share that master. An explicit override equal to the global label still uses a versioned master, allowing the project to remain pinned across future global switches.

Starting PHP or a web server starts all required masters. Automatic scanning checks `.php-version` metadata every five seconds and starts new masters **before** a checked web reload. Newly started masters are stopped if the update fails; prior vhost includes are restored. A global PHP switch rebuilds the stack but preserves each project's explicit selection. PHP stop/restart and controller shutdown include all override masters.

Unused masters are retained after a live selector removal/change until PHP stop/restart, to avoid interrupting old web-worker requests. They are marked `required: false` in the `php_pools` status array. There is no per-child automatic crash restart policy; inspect status and logs and use Restart PHP as needed.

`localforge status` reports per-pool PID, socket, required/running flags and errors. The GUI's PHP selector tooltip exposes these details; per-version logs are selectable in Logs & ports. The global private CLI shim is **not** changed by entering a project directory. Shell-level automatic PHP switching is outside this change.

## Validation scope

64 tests currently pass: 50 core/hosts/installer-harness tests and 14 native engine/RPC tests. Native tests cover both web servers' Adminer HTML/CSS routes, no-source behavior, unrelated-Host rejection, distinct per-label FPM routing, live selector changes, global-switch pinning, startup rollback and MariaDB over a shortened socket path. Different per-label php.ini timezone markers on the same installed PHP binary prove routing; they do **not** prove PHP 7.4/8.1/8.2/8.3 binary compatibility. Interactive Adminer SQL login, enforcing Fedora labeling and Arch/Fedora installers remain desktop release gates.
